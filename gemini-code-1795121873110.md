# Technical Requirements Document (TRD) — Application de Vente en Ligne

## 1. Architecture globale
Architecture client-serveur modulaire :
* **Frontend** : application web (SPA/SSR) ou mobile consommant une API REST ou GraphQL.
* **Backend** : services applicatifs exposant les endpoints métier (authentification, catalogue, panier, commandes, paiements, administration).
* **Base de données relationnelle** : stockage structuré des utilisateurs, produits, stocks, commandes et transactions.
* **Stockage d'objets (Object Storage)** : hébergement des images produits et médias statiques via CDN.
* **Passerelle de paiement externe** : traitement sécurisé des transactions (redirection ou composant hébergé, sans stockage direct des données sensibles de carte).

## 2. Stack technique recommandée (à adapter selon l'équipe)
* **Frontend** : Next.js / React ou Vue / Nuxt (TypeScript, Tailwind CSS) ; ou Flutter / React Native pour le mobile.
* **Backend** : Node.js (NestJS / Express), Python (FastAPI / Django) ou Laravel.
* **Base de données** : PostgreSQL (avec Prisma / TypeORM / SQLAlchemy).
* **Cache / Sessions (optionnel MVP)** : Redis pour le cache catalogue ou les verrous/sessions si nécessaire.
* **Hébergement & CI/CD** : Vercel / Render / Railway / AWS / VPS + Docker + GitHub Actions.

## 3. Modèle de données principal
* **Users** : `id`, `email`, `password_hash`, `full_name`, `phone`, `role` (`customer` | `admin`), `created_at`.
* **Addresses** : `id`, `user_id`, `label`, `street`, `city`, `country`, `postal_code`, `is_default`.
* **Categories** : `id`, `name`, `slug`, `parent_id`.
* **Products** : `id`, `category_id`, `title`, `slug`, `description`, `price_cents`, `currency`, `stock_quantity`, `image_url`, `is_active`, `created_at`.
* **Carts & CartItems** : `cart_id`, `user_id` (ou `session_id`), `product_id`, `quantity`.
* **Orders & OrderItems** : `id`, `order_number`, `user_id`, `status`, `subtotal_cents`, `shipping_cents`, `total_cents`, `shipping_address_json`, `created_at` ; lignes figées (`product_id`, `product_title_snapshot`, `unit_price_cents`, `quantity`).
* **Payments** : `id`, `order_id`, `provider`, `provider_reference`, `amount_cents`, `status` (`pending` | `paid` | `failed` | `refunded`), `paid_at`.

## 4. Sécurité
* **Authentification & Autorisation** : mots de passe hachés avec Argon2 ou bcrypt, tokens JWT (access + refresh) ou sessions sécurisées, contrôle d'accès basé sur les rôles (`RBAC`) pour les routes admin.
* **Protection API** : validation stricte des entrées, protection CORS, rate limiting sur l'authentification et le checkout, requêtes paramétrées contre l'injection SQL.
* **Paiements** : vérification des webhooks de la passerelle de paiement avec signature cryptographique et traitement idempotent.
* **Gestion des stocks** : décrémentation atomique en transaction base de données lors de la validation de commande pour prévenir les conditions de concurrence (*race conditions*).

## 5. APIs & Intégrations clés
* **Auth** : `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`, `GET /api/me`.
* **Catalogue** : `GET /api/products`, `GET /api/products/:slug`, `GET /api/categories`.
* **Panier** : `GET /api/cart`, `POST /api/cart/items`, `PATCH /api/cart/items/:itemId`, `DELETE /api/cart/items/:itemId`.
* **Commandes & Paiement** : `POST /api/orders`, `GET /api/orders`, `GET /api/orders/:id`, `POST /api/payments/webhook`.
* **Admin** : `POST/PATCH/DELETE /api/admin/products`, `PATCH /api/admin/orders/:id/status`.
* **Services externes** : passerelle de paiement adaptée à la zone cible (ex. Stripe, Paystack, Flutterwave, Mobile Money selon le marché), service d'e-mails transactionnels (confirmation de commande).

## 6. Déploiement, Observabilité & Tests
* **Environnements** : `development`, `staging` (environnement de test proche de la production), `production`.
* **CI/CD** : exécution automatique des tests et vérifications de lint/build à chaque pull request avant déploiement.
* **Observabilité** : logs structurés, suivi des erreurs applicatives (ex. Sentry) et alertes sur les endpoints critiques (checkout et webhooks paiement).
* **Stratégie de test** : tests unitaires sur la logique métier (calcul des totaux, règles de stock, transitions de statuts), tests d'intégration sur l'API et tests end-to-end (E2E) sur le parcours d'achat complet.
